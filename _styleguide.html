02 · Type

Type

Robots that see in three dimensions

Stereo depth on a Raspberry Pi 5

Point cloud filtering and downsampling

Voxel grid at 2 cm resolution

I build perception and autonomy software for mobile robots: from camera calibration to SLAM, path planning and the glue code that keeps it running on real hardware.

Polaris is a small differential-drive rover that maps its surroundings with a depth camera and an IMU. The perception stack fuses visual odometry with wheel encoders, builds an occupancy grid, and replans around obstacles at ten hertz. Most of the hard work is not the algorithms themselves but making them robust to motion blur, poor lighting and a CPU that is also running everything else. Read the Polaris write-up for the full build log.

Why the robot runs on a Pi

Running the whole autonomy stack on a single-board computer forces honest engineering. There is no discrete GPU to hide inefficiencies, so every node has to justify its CPU budget. The depth pipeline downsamples early, the planner works on a coarse grid, and logging is batched so the SD card is not a bottleneck.

That constraint also makes the robot cheap to rebuild. If a motor driver burns out during a test run, the replacement costs less than a lunch, and the software stack comes back with a single provisioning script.

Calibration is never finished

Camera intrinsics drift when the lens gets knocked, and extrinsics between the camera and the IMU change every time the chassis is reassembled. Polaris runs a quick checkerboard routine at startup and compares the reprojection error against the last known good value. If it creeps above half a pixel the robot refuses to map and asks for a full recalibration.

It sounds fussy, but a few tenths of a degree of rotation error between sensors turns into walls that bend and doorways that close up on the map after a few metres of travel.

From point cloud to occupancy grid

Each depth frame becomes a point cloud of roughly three hundred thousand points. A voxel filter brings that down to a few thousand, a ground plane fit removes the floor, and the remaining points are projected into a 2D occupancy grid with five-centimetre cells. Ray casting clears free space between the camera and each hit, so moving people do not leave permanent ghosts behind.

The grid feeds a hybrid A* planner that respects the rover's turning radius, followed by a pure-pursuit controller that tracks the path at walking speed.

What comes next

The next milestone is semantic mapping: labelling regions of the grid as kitchen, hallway or doorway so that high-level commands like "go to the kitchen" make sense. That means running a segmentation model alongside the detector without blowing the thermal budget, which is its own small research project.

Progress, failures and the occasional crash into the sofa are all logged on the Polaris page, which pulls live status from the robot itself.
