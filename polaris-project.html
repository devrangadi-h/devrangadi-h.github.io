Polaris: A Raspberry Pi Assistant

Polaris is a personal assistant that runs on a Raspberry Pi 5 at home. It maintains this website, reports its own health, runs my floor lamps, and writes a public log of every change it makes. It runs an OpenClaw agent, plus a few small services I wrote around it.

I built it to find out what it takes to make a small, always-on system that you can trust: one that tells you when it’s broken instead of quietly failing.

Hardware

  • Raspberry Pi 5 (16 GB) running Raspberry Pi OS. Always on and headless
  • USB webcam for the flower tracker
  • Two Govee H607C floor lamps, controlled through Govee’s cloud API

How it works

1. Editing the website

This site is a static site on GitHub Pages, with Cloudflare in front for HTTPS. The Pi keeps a clone of the repository. When I ask Polaris for a change, it edits the files, adds an entry to polaris-log.json, and commits and pushes. GitHub Pages redeploys within a minute or two, and the dashboard shows the new log entry.

2. Reporting its own health

Every 15 minutes a small Python script collects the Pi’s CPU temperature, load, memory and disk usage, writes them to a JSON file and pushes it. The dashboard reads that file. If the latest report is more than 35 minutes old, it shows the Pi as offline, along with when it was last seen.

3. Controlling the lights

A tiny Flask API on the Pi turns the lamps on and off, sets brightness and switches between warm and cool white. Since it controls something physical, I locked it down:

  • It only listens on the Pi itself. Tailscale Serve gives it an HTTPS address that only my own devices can reach, so it isn’t on the public internet.
  • Every request needs an access token, which the Pi checks. The page stores nothing secret.
  • The API only answers browser requests from this site, and the Govee API key never leaves the Pi.

4. The flower tracker

A systemd timer grabs a webcam frame every five minutes with ffmpeg and publishes it to the dashboard. If the camera is unplugged, the job skips quietly and the dashboard hides the section until fresh snapshots arrive.

Lessons learned

“Online” isn’t a status, it’s a claim

In July 2026 a few objects in the Pi’s local git repository were corrupted. Every status push after that failed silently. The dashboard kept showing Online, because the status file said so, with a timestamp from early July, for three months. I repaired the repository and changed the dashboard to judge freshness itself. Now a missed report shows up as offline within 35 minutes.

Security in a static site lives somewhere else

The first version of the lights panel was gated by a password checked in the browser, so anyone could read it in the page source. The repository also published the Pi’s backend scripts, since GitHub Pages serves everything in a repo. Both are fixed: the backend now lives outside the website, and the server checks the token.

Small automations need housekeeping

Pushing a status update every five minutes added more than 34,000 commits to the repository. Reporting every 15 minutes cuts that down a lot, and the dashboard is still fresh enough to be useful.
